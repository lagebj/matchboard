# Gate C W2 — Blockers and Known Limitations

## Genuine source gaps (not fixed, disclosed)

- **C06-B position precision**: Round Board has no exact tactical-position field anywhere in its data model. The 24-code/14-code contrast the register's acceptance question names belongs to the separate Lineup/Formation editor. A fourth remediation pass split this from C06-A (dense allocation, demonstrated) and added an explicit owner decision record — see `POSITION_VOCABULARY_AND_PRECISION.md`. Disposition: `BLOCKED_BY_SOURCE_OR_AUTHORITY`, unaffected by the Lineup link's navigation correction below.

## Fixed during remediation (previously listed here as unfixed — see `REVIEW_RECORD.md` for the full finding-by-finding disposition)

- **A rejected assignment now shows the real reason and leaves state unchanged** (remediation finding P1-05). `movePlayerToMatch` returns a structured `{status: "success" | "rejected" | "error", reason?}` outcome instead of a bare void; every caller only refreshes/closes on a genuine success, and a shared error surface (inline in the assignment inspector/sheet when a player is selected; a dismissible top-level banner otherwise) shows the real reason. A genuine partial-completion risk (add succeeds, the subsequent remove fails) is surfaced as an explicit error rather than a silent success — not hidden behind a redesigned transaction, which stays out of this wave's scope.
- **The source match's boundary is now guarded too, not only the destination** (P1-03). `movePlayerToMatch` now checks both sides before doing anything; a player whose own current match has closed can no longer be removed from it as a side effect of a matrix toggle or suggestion-card assignment into a different, open match. The suggestion-card/inspector path additionally stopped *offering* a destination at all once the player's own match is closed (proactive, not just reactive) — found and fixed during this remediation's own test-writing, beyond the review's literal wording.
- **Resolve is now gated on a real per-match boundary, not merely on `onResolve` being provided** (P1-01). `RoundBoardAttentionItem.resolvable` is computed by the production adapter from the same per-match `isFinalized` data it already receives; the rail renders the control only when it is actually `true`.
- **Production signal identity (`playerId`/`matchId`/`idempotencyKey`) is no longer dropped** between `compute-plan-integrity.ts` and the board (P1-04) — `page.tsx`'s warning mapping now carries all three through, and `attentionItems` uses the real identifiers instead of a hardcoded `null` `matchId` and an array-index-derived `id`.
- **`CoachingIntentSelector`'s own dynamically-imported server actions are now isolated from UI Lab** (P1-06) via two new optional command props, defaulting to the real actions in production. Clear/Regenerate have no deterministic fixture behavior to offer, so the UI Lab harness disables both outright (`disableClearAndRegenerate`) with an explanatory `title`, rather than a no-op that would look like it worked.
- **C05's retained historical warning is now one the real plan-integrity engine can actually produce for a finalized match** (P1-02) — `SQUAD_BELOW_MINIMUM` (evaluated across both draft and finalized selections, for every non-cancelled match regardless of planning boundary) replaces an earlier draft's `SELECTED_PLAYER_UNAVAILABLE`, which the engine only ever emits for `DRAFT` selections and can therefore never legitimately co-occur with a finalized/closed match.
- **Browser (not just component-test) evidence now exists for C04-C06** (P1-07): `scripts/ui-lab-visual-review.mjs` registers C04, C05, and C06's primary routes in the CI screenshot-capture pipeline; `e2e/ui-lab-gate-c.spec.ts` gained 29 new real-Chromium Playwright acceptance tests covering the coverage denominator, Resolve gating, the dense matrix, the mobile sheet, a genuinely denied assignment (navigating directly to the dedicated denied-assignment route), and that no mutation-capable control reaches a real `next-action` request from this fixture. **Correction, found while verifying real CI attestation evidence for the second remediation pass**: the denied-assignment sub-route itself was never added to the screenshot-capture pipeline (only its parent C06 route was) — it has real Playwright acceptance coverage (the test above) and its own responsive-overflow coverage, but no capture-attestation screenshot entry. The prior claim here that all four routes were capture-registered was inaccurate; corrected rather than left standing.

## Fixed during the second remediation pass (previously listed as resolved above, re-opened and corrected — see `REVIEW_RECORD.md`'s "Second remediation pass findings" table)

- **Resolve eligibility now checks the player's OWN match, not just whether some other match is open.** The first remediation pass's `resolvable` fix (P1-01) left a gap: a player assigned to a CLOSED match could still be marked `resolvable: true` because a different match happened to be open. `isResolvable` now checks the player's own current match first and fails closed if it is not open.
- **Match-specific Resolve now has a real effect on desktop.** Previously it only updated mobile-only state. A new `handleResolveMatch` callback scrolls the real match lane into view and focuses a real control inside it, exercised by the new `c05-planning-closed/open-match-warning` route.
- **The mixed-boundary banner no longer claims every match is closed when only some are.** The round-level all-or-nothing gate (see `CLOSED_STATE_RULES.md`) is now narrated accurately: "Round-wide planning locked" / "Some matches have closed..." for a mixed boundary, vs. "Planning closed" / "All matches have passed..." when every match has actually closed.
- **The desktop Move picker no longer offers closed destinations.** It had never had the suggestion-card path's `isFinalized` filter applied. Fixed, with a distinct empty-state message for "other matches exist, but closed" vs. "no other matches exist."

## Fixed during the third remediation pass (previously listed as resolved above, re-opened and corrected — see `REVIEW_RECORD.md`'s "Third remediation pass findings" table)

- **Match-specific Resolve now reaches a genuine correction, not just navigation.** The second pass's fix scrolled to and focused an already-ASSIGNED player's own "Select" control — but that player's own current match is always excluded as a destination for themselves, so the workflow could never add anyone to a squad that is short. Resolve now directs the coach at the real "Available" (unassigned) list instead, retaining the target through candidate selection and marking the actual shortage match as the dominant recommendation.
- **Resolve eligibility now independently checks the warning's own OWNING match.** The second pass's fix only checked the player's current match; a warning naming a CLOSED match could still be marked resolvable because the player was unassigned or assigned elsewhere. `isResolvable` now fails closed on the signal's own `matchId` first, decisively, before considering the player at all.
- **Mobile focus can no longer land on a CSS-hidden desktop control.** The focus-target query previously picked the first DOM match regardless of which composition's CSS currently hides it. A new `isMobileCompositionVisible` flag (the literal `medium` breakpoint, distinct from the unrelated `isCompactViewport` dialog-style threshold) scopes every query to one of two new explicit containers.
- **A frozen fixture-warning limitation found and disclosed while building this pass's own correction-workflow evidence**: the UI Lab fixture harness's `warnings` prop is a static snapshot, never recomputed after a mutation (recomputing it would mean a second plan-integrity engine, which the brief forbids) — so a committed assignment's test evidence asserts the real, truthful squad-count/available-list updates, and explicitly does NOT assert that the original warning text disappears. See `DATA_TRUTH_AND_FIXTURES.md`'s dedicated section.

## Fixed during the fourth remediation pass (previously listed as resolved above, re-opened and corrected — see `REVIEW_RECORD.md`'s "Fourth remediation pass findings" table)

- **C06's Lineup link now uses the canonical organisation-scoped route.** The legacy `/matches/{matchId}` route silently fails for a multi-organisation user (`resolveOrgSlugForLayout()` redirects to `/organisations` instead of the match whenever a user belongs to more than one organisation — confirmed by direct read of `src/lib/auth/resolve-org-slug.ts`). `RoundBoard` now takes a plain `orgSlug: string` prop (never `useOrgUrl()`/`useOrgSlug()` called directly inside it, which would throw in UI Lab/tests) and builds `/o/{orgSlug}/matches/{matchId}`. The link's label also changed from "View exact position in Lineup" to "Open Lineup" — Round Board cannot know whether an exact position already exists at the destination.
- **C06's acceptance question is now explicitly split, rather than implicitly resolved by navigation.** A fourth independent review correctly identified that the Lineup link (added in an earlier pass) is correct navigation, not proof that the original 24-vs-14-role question is answered. `POSITION_VOCABULARY_AND_PRECISION.md` now separates C06-A (dense allocation, demonstrated) from C06-B (position precision, still `BLOCKED_BY_SOURCE_OR_AUTHORITY`), with an explicit two-option decision record left for the repository owner.

## Genuine source gaps, re-affirmed by the fourth remediation pass (not fixed, disclosed, unaffected by the navigation correction above)

- **C06-B position precision**: unchanged. The navigation fix above corrects *where the link points*, not *what Round Board knows*. Round Board still has no exact tactical-position field anywhere in its data model. See `POSITION_VOCABULARY_AND_PRECISION.md`. Disposition: `BLOCKED_BY_SOURCE_OR_AUTHORITY`.

## Pre-existing, documented, not remediated here

- **Issue #827** (ADR-0159 Visual Authority fingerprint invalidation from a shared-fixture edit) remains open and separately tracked. This wave avoided reproducing its trigger (see `DATA_TRUTH_AND_FIXTURES.md`'s "new, not reused" fixture architecture) but did not fix the underlying fingerprinting behavior.
- **Allocation matrix unreachable in any closed-boundary round**: a real, low-severity consequence of existing gating (the Board/Allocation toggle only renders when `planningBoundaryOpen` is true, which requires every match open) — see `CURRENT_STATE_AUDIT.md` item 5. Not a defect; `handleMatrixToggle`'s own `isFinalized` guard is simply unreachable in production as currently gated. Not fixed — out of this wave's bounded scope.
- **No safe desktop width between ~840px and ~1200px for Round Board's current grid**: found while writing this wave's own Playwright responsive-layout tests — the desktop workbench grid (three match-lane columns at `minmax(220px,...)` plus the available/inspector columns) genuinely overflows a 768px or 900px viewport. Reproduced identically on the untouched, already-merged `atlas-followup/round-board` prototype at 768px, confirming this is pre-existing and unrelated to this wave. Not fixed — a layout redesign of the desktop grid's minimum column widths is a materially larger change than any of the remediation findings asked for. **Filed as a separately tracked defect**: https://github.com/lagebj/matchboard/issues/830 (labeled `bug`), per the second remediation pass's instruction not to hide this limitation behind a broad responsive redesign.
