# Gate C W2 — Blockers and Known Limitations

## Genuine source gaps (not fixed, disclosed)

- **C06 position precision**: Round Board has no exact tactical-position field anywhere in its data model. The 24-code/14-code contrast the register's acceptance question names belongs to the separate Lineup/Formation editor. See `POSITION_VOCABULARY_AND_PRECISION.md`. Disposition: `BLOCKED_BY_SOURCE_OR_AUTHORITY`.

## Fixed during remediation (previously listed here as unfixed — see `REVIEW_RECORD.md` for the full finding-by-finding disposition)

- **A rejected assignment now shows the real reason and leaves state unchanged** (remediation finding P1-05). `movePlayerToMatch` returns a structured `{status: "success" | "rejected" | "error", reason?}` outcome instead of a bare void; every caller only refreshes/closes on a genuine success, and a shared error surface (inline in the assignment inspector/sheet when a player is selected; a dismissible top-level banner otherwise) shows the real reason. A genuine partial-completion risk (add succeeds, the subsequent remove fails) is surfaced as an explicit error rather than a silent success — not hidden behind a redesigned transaction, which stays out of this wave's scope.
- **The source match's boundary is now guarded too, not only the destination** (P1-03). `movePlayerToMatch` now checks both sides before doing anything; a player whose own current match has closed can no longer be removed from it as a side effect of a matrix toggle or suggestion-card assignment into a different, open match. The suggestion-card/inspector path additionally stopped *offering* a destination at all once the player's own match is closed (proactive, not just reactive) — found and fixed during this remediation's own test-writing, beyond the review's literal wording.
- **Resolve is now gated on a real per-match boundary, not merely on `onResolve` being provided** (P1-01). `RoundBoardAttentionItem.resolvable` is computed by the production adapter from the same per-match `isFinalized` data it already receives; the rail renders the control only when it is actually `true`.
- **Production signal identity (`playerId`/`matchId`/`idempotencyKey`) is no longer dropped** between `compute-plan-integrity.ts` and the board (P1-04) — `page.tsx`'s warning mapping now carries all three through, and `attentionItems` uses the real identifiers instead of a hardcoded `null` `matchId` and an array-index-derived `id`.
- **`CoachingIntentSelector`'s own dynamically-imported server actions are now isolated from UI Lab** (P1-06) via two new optional command props, defaulting to the real actions in production. Clear/Regenerate have no deterministic fixture behavior to offer, so the UI Lab harness disables both outright (`disableClearAndRegenerate`) with an explanatory `title`, rather than a no-op that would look like it worked.
- **C05's retained historical warning is now one the real plan-integrity engine can actually produce for a finalized match** (P1-02) — `SQUAD_BELOW_MINIMUM` (evaluated across both draft and finalized selections, for every non-cancelled match regardless of planning boundary) replaces an earlier draft's `SELECTED_PLAYER_UNAVAILABLE`, which the engine only ever emits for `DRAFT` selections and can therefore never legitimately co-occur with a finalized/closed match.
- **Browser (not just component-test) evidence now exists for C04-C06** (P1-07): `scripts/ui-lab-visual-review.mjs` registers all four new routes (including the dedicated denied-assignment variant); `e2e/ui-lab-gate-c.spec.ts` gained 29 new real-Chromium tests covering the coverage denominator, Resolve gating, the dense matrix, the mobile sheet, a genuinely denied assignment, and that no mutation-capable control reaches a real `next-action` request from this fixture.

## Pre-existing, documented, not remediated here

- **Issue #827** (ADR-0159 Visual Authority fingerprint invalidation from a shared-fixture edit) remains open and separately tracked. This wave avoided reproducing its trigger (see `DATA_TRUTH_AND_FIXTURES.md`'s "new, not reused" fixture architecture) but did not fix the underlying fingerprinting behavior.
- **Allocation matrix unreachable in any closed-boundary round**: a real, low-severity consequence of existing gating (the Board/Allocation toggle only renders when `planningBoundaryOpen` is true, which requires every match open) — see `CURRENT_STATE_AUDIT.md` item 5. Not a defect; `handleMatrixToggle`'s own `isFinalized` guard is simply unreachable in production as currently gated. Not fixed — out of this wave's bounded scope.
- **No safe desktop width between ~840px and ~1200px for Round Board's current grid**: found while writing this wave's own Playwright responsive-layout tests — the desktop workbench grid (three match-lane columns at `minmax(220px,...)` plus the available/inspector columns) genuinely overflows a 768px or 900px viewport. Reproduced identically on the untouched, already-merged `atlas-followup/round-board` prototype at 768px, confirming this is pre-existing and unrelated to this wave. Not fixed — a layout redesign of the desktop grid's minimum column widths is a materially larger change than any of the seven remediation findings asked for.
