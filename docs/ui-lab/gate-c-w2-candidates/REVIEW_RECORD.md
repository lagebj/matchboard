# Gate C W2 — Review Record

## Summary

Three candidates (C04, C05, C06 — plus a dedicated denied-assignment route for C06) built against the real, unmodified `RoundBoard` production component tree, via a fixture command boundary that never touches a live database mutation. The initial implementation found and fixed two real production defects (eligible-coverage data never surfaced; a closed match could still accept an assignment from the inspector/sheet) and correctly disclosed C06's position-precision gap as `BLOCKED_BY_SOURCE_OR_AUTHORITY` rather than fabricating it.

An independent review of that implementation found seven further findings (P1-01 through P1-07). All seven were fixed in that pass, verified with real browser tests in addition to component tests, and documented below finding-by-finding.

A second independent review (of HEAD `af686e3cd8cf0a0633f18d931bb47bf7a6eca590`) found that two of those fixes (P1-01, P1-03) were incomplete in a specific way neither pass's original tests exercised, plus two further defects. All four are fixed in this second remediation pass — see "Second remediation pass findings" below.

A third independent review (of HEAD `c03f148e4d4e6a7448fc7a375509043e0d7c5040`) found that the second pass's own Resolve fixes were still not enough: scrolling to and focusing a control is navigation, not a genuine correction path, and the player-specific `resolvable` check still didn't account for the warning's own owning match independently of the player's current one. Three further findings, all fixed — see "Third remediation pass findings" below.

A fourth independent review (of HEAD `962d1449fd477ccc265dc206f2d28a6b61d131a9`) found: (W2-F01) the C06 Lineup link used the legacy, unscoped organisation route, which silently fails to resolve for a multi-organisation user; (W2-F02) C06's navigation addition does not, by itself, demonstrate the original 24-vs-14 position-precision acceptance question — that requires an explicit decision record, not a code fix; (W2-F03) the wave's own visual-vs-current documentation did not clearly separate "existing design confirmed" from "behavior corrected" from "actual visual change," risking an owner misreading passing tests as visual approval. W2-F01 is fixed in this pass; W2-F02 and W2-F03 are resolved by documentation (a decision record and a restructured visual comparison), not code — see "Fourth remediation pass findings" below.

## Found and fixed while generating this pass's own real CI attestation evidence

- **The real CI run initially crashed, not merely failed.** The first push of this pass's fixes crashed the entire `ui-lab-visual-review.yml` capture job with an uncaught `TimeoutError`: the new `move-picker-excludes-closed` capture-script interaction clicked the chip's "Move Markus to..." button unconditionally, but that button is genuinely absent from the accessibility tree below the desktop breakpoint (CSS-hidden via `hidden medium:grid`), so `getByRole` never found it on the mobile viewport variant and the 30s timeout aborted the whole run. Fixed with an `isVisible()` guard (same precedent as the existing Allocation-toggle interaction); verified locally against a real Chromium instance across all five viewport widths the scenario captures before re-pushing. The corrected run completed green (98 Gate C Playwright tests, capture job success).
- **A pre-existing documentation inaccuracy from the first remediation pass.** Several documents (`BLOCKERS_AND_KNOWN_LIMITATIONS.md`, `SCENARIO_REGISTER.md`, `CHANGED_FILES.md`, this document's own P1-07 row, `candidate_manifest.json`) claimed the capture script registered "all four" C04-C06 routes, including the dedicated denied-assignment sub-route. Direct inspection of the real CI artifact (no `gate-c-w2-c06-dense-allocation-denied-assignment-*.png` files exist in it) showed this was false — only C04/C05/C06's three primary routes were ever capture-registered; the denied-assignment behavior is real-browser-tested, just via a dedicated Playwright acceptance test (`ui-lab-gate-c.spec.ts`), not a screenshot. Corrected in place rather than left standing, per this pass's own instruction not to let evidence claims outrun what was actually verified.
