## Edge cases (exercised as fixture-builder-function variants, not separate routes — per the brief's own instruction)

- **C04**: `buildC04NoEligiblePlayersFixture` (zero eligible players — no division by zero), `buildC04AllAssignedFixture` (every eligible player covered), `buildC04SeveralMissingFixture` (three players missing an opportunity across two teams, never collapsed into one row).
- **C05**: `buildC05ClosedNoWarningFixture` (closed round, nothing unresolved), `buildC05FullyOpenControlFixture` (control case — a fully open round where Resolve is genuinely valid), `buildC05OpenMatchWarningFixture` (a match-only warning on a still-open match — Resolve now reaches the real Available-column correction workflow), `buildC05OpenMatchWarningDeniedFixture` (same, plus a deliberately rejected commit — third remediation pass), `buildC05InsufficientIdentityFixture` (a warning with neither a player nor a match identity — fails safe to read-only).
- **C06**: `buildC06WithDeniedAssignmentFixture` (a deliberately rejected cross-team assignment — proves the UI never shows a successful result before a real accepted one; also exposed as its own route, above).

Each variant has direct component-test coverage in its scenario's `__tests__/page.test.tsx` (24 tests total across the three scenarios: 6 C04 + 12 C05 + 6 C06 — unchanged by either remediation pass, both of which added new routes rather than new page-level tests) plus real-browser coverage in `e2e/ui-lab-gate-c.spec.ts` (35 Playwright tests under the `ui-lab-gate-c` project — 29 from the first remediation pass, 2 from the second, 4 from the third — run locally against `next dev` and in CI). See `VISUAL_VS_CURRENT.md` for what each proves and `CURRENT_STATE_AUDIT.md` item 5 for the one genuinely untestable edge case (a closed round's allocation matrix, which the production component makes structurally unreachable).
