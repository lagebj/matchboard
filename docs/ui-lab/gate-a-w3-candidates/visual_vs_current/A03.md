# A03 — Decision anatomy: current-state comparison (XR-V01)

**Coach question:** For a specific match decision, can I see what needs action, why, what I'm
allowed to do about it, and what would change — without reading a generic dashboard?

## Current-state baseline

`NO_BASELINE_CAPABILITY`. No current production surface renders this exact four-part grammar
(situation → permitted/unavailable action → consequence → inspectable reason) as one coherent unit
for a single match decision. The closest real components are `TodayNextAction`
(`src/components/touchline/today/today-next-action.tsx`) and Round Board's plan-integrity signal
rendering, but neither exposes an inline "expected consequence" disclosure or a closed-state
read-only review with the same explicit absence of a mutating control — confirmed by direct read
before building this candidate.

## A03-S1 — actionable decision (planning open)

- **Current-state deficiency:** no equivalent exists to compare against.
- **Proposed difference:** names the affected player (Tobias) and slot (RCM) explicitly in the
  situation text; the permitted action is a real, enabled control; clicking it reveals the
  expected consequence inline (no navigation); a separate "Why?" toggle shows the inspectable
  reason, sourced to a fixture-labelled fact, not invented prose.
- **User-impact proof:** a reviewer can name the exact object, decision, and reason from this one
  screen without opening a second analytics view.
- **Accepted trade-off:** the permitted action is illustrative only (no mutation) — see
  `BLOCKERS.md`.

## A03-S2 — closed plan review

- **Current-state deficiency:** no equivalent exists to compare against.
- **Proposed difference:** zero mutating controls anywhere on the page (verified by test:
  `screen.queryByRole("button", { name: /assign|save|resolve/i })` is `null`); "Review plan" only
  ever opens a read-only explanation, never implies an exception.
- **User-impact proof:** a reviewer cannot find an executable-looking action in a closed state —
  the rejection test this candidate's own spec calls for ("disabled action still looks executable")
  has nothing to find here.
- **Accepted trade-off:** none specific to this case.

## A03-S3 — permission denied

- **Current-state deficiency:** no equivalent exists to compare against.
- **Proposed difference:** the denied actor sees only the minimal match identity and the denial
  reason — the squad, the pending starter, and the unfilled slot are never rendered on this page at
  all (verified by test: "Tobias"/"RCM" never appear in the rendered output).
- **User-impact proof:** a reviewer can confirm no private planning detail leaks to a denied
  viewer, by inspecting this one page.
- **Accepted trade-off:** this is a UI honesty test, not a security test of the real authorization
  service — see `BLOCKERS.md`.

## A03-S4 — Round Board integrity signal

- **Current-state deficiency:** no equivalent exists to compare against.
- **Proposed difference:** the signal states a fact and points back to the match/round by name,
  with no second "Resolve" affordance and no alternate fairness/eligibility calculation rendered
  anywhere on the page.
- **User-impact proof:** a reviewer can confirm the signal is a pointer, not a second decision
  engine, by the simple absence of any resolving control.
- **Accepted trade-off:** none specific to this case.
