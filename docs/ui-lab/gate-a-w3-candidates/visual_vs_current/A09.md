# A09 — Today quick action: current-state comparison (XR-V01, XR-I01)

**Coach question:** Can I add an eligible player to today's match straight from Today, see
exactly why an ineligible candidate is blocked, and tell a normal planned addition apart from a
separate match-day addition — all without a detour through Match Details?

## Current-state baseline

`NO_BASELINE_CAPABILITY` for the quick-action flow itself: `TodaySurface`/`TodayNextAction`
(`src/components/touchline/today/`) own Today's situational ranking and next-action copy, but
confirmed by direct read — neither exposes a context-local "add player" entry point today; the
closest real action is `AddPlayerDialog`, which lives in Match Details, not Today, and pre-filters
candidates server-side with no visible excluded-with-reasons list (a different shape from what
this candidate needs).

## A09-S1 — permitted candidate, success

- **Current-state deficiency:** no equivalent exists on Today today.
- **Proposed difference:** open → select → diff preview ("8/9 → 9/9 — draft, not yet saved") →
  confirm → `PENDING` (fixture-simulation gate) → "Saved (simulated)", entirely inside a
  Today-anchored sheet/inspector.
- **User-impact proof:** the count only ever changes after a genuine resolved `SUCCESS` (verified
  by test), never optimistically.
- **Accepted trade-off:** simulated save — see `BLOCKERS.md`.

## A09-S2 — actor/group denied (blocked at entry)

- **Current-state deficiency:** `AddPlayerDialog` shows no excluded candidates at all (pre-filtered
  server-side); there is nothing to compare a "visible denial reason" against.
- **Proposed difference:** the candidate row is visibly present but disabled, with its denial
  reason stated plainly, rather than silently omitted.
- **Accepted trade-off:** this is the "disabled at entry" case by design — denial-after-preview is
  covered separately by S4/S5, per the bundle's own requirement that at least one negative fixture
  per family show denial arising after opening, not only a disabled button at entry.

## A09-S3 — RSVP deadline passed, no response

- **Current-state deficiency:** `NO_BASELINE_CAPABILITY` — Matchboard has no automated
  deadline-driven RSVP-decline mechanism in source at all (confirmed: no scenario, type, or
  deadline-decline logic found anywhere in `src`; see `CURRENT_STATE_AUDIT.md`). This fixture is
  therefore illustrative of a policy Matchboard does not yet implement, not a reproduction of an
  existing one.
- **Proposed difference:** the blocked candidate's reason is stated plainly, with a disclosed,
  non-interactive note that a separate match-day-addition workflow may exist on the day of the
  match without rendering that workflow for this candidate (the fixture does not support it for
  Jonas specifically).
- **Accepted trade-off:** see `BLOCKERS.md` item 1 — a real product decision is needed before this
  policy can be implemented.

## A09-S4 — planning closed after preview

- **Current-state deficiency:** no equivalent exists to compare against.
- **Proposed difference:** the count stays at 8 (verified by test) even after a full
  open→select→preview→confirm sequence — `planning_closed` never silently updates the count.
- **Accepted trade-off:** none specific to this case.

## A09-S5 — stale revision / already a participant

- **Current-state deficiency:** `NO_BASELINE_CAPABILITY` — no production Today/roster-add action
  exposes a revision fingerprint today.
- **Proposed difference:** "Already a participant — recheck match" with expected/current revision,
  count unchanged, no duplicate add, no auto-merge.
- **Accepted trade-off:** illustrative only — see `BLOCKERS.md` item 3.

## A09-S6 — match-day addition (separate operational path)

- **Current-state deficiency:** `NO_BASELINE_CAPABILITY` for the Today surface specifically; the
  real operational path (`addLeagueMatchHelperAction` with `provenance: "MATCH_DAY_ADDITION"`,
  gated by `assertLeagueMatchHelperEligible`) exists in Match Details' `AddPlayerDialog`, not
  Today.
- **Proposed difference:** a visibly separate "Operational roster" counter (8→9) sits alongside an
  always-visible, unchanged "Planned squad: 8/9" line — the two never merge into one number.
- **User-impact proof:** a reviewer can see, on one screen, that a match-day addition does not
  silently inflate the planned-selection count (verified by test: the planned-squad text node is
  asserted separately and unchanged throughout).
- **Accepted trade-off:** this candidate's eligibility reasoning mirrors ADR-0077's real, narrow
  `assertLeagueMatchHelperEligible` scope but does not invoke that function — see `BLOCKERS.md`
  item 2.

## Cross-cutting proof (all six scenarios)

Two real bugs were found and fixed while building this candidate (see `CURRENT_STATE_AUDIT.md`
"Real bugs found and fixed" #2–#3): a double-incremented saved count and a duplicate,
ambiguously-named "Discard draft" control. Both were caught by this candidate's own component
tests before shipping, not discovered after the fact.
