# A05/A08 — Assistant Coach semantic grammar and activation parity: current-state comparison

**Coach question:** When Assistant Coach is off, has a useful pattern, has nothing useful, or has
failed, can I tell which one is happening — and does every state preserve the deterministic facts
I'd otherwise rely on?

## Current-state baseline

`PARTIAL_BASELINE`. The real `AssistantCoachHypothesisPanel` (`src/components/ai/assistant-coach-
hypothesis-panel.tsx`) already implements the correct "no reserved gap when empty" behaviour
(`if (hypotheses.length === 0) return null;`) and the correct uncertainty/evidence-ref/missing-
evidence vocabulary — this candidate is not inventing new semantics, it is reproducing the real
component's visual grammar in a form that is actually fixture-injectable (see `BLOCKERS.md`
W4-BLK-10). What the real component does NOT do today is distinguish "off" from "ran, found
nothing" at the presentation layer — both currently render nothing (`return null`), which is
correct for "off" but loses the honest "ran, found nothing" signal A08's own acceptance question
asks for.

## A05-disabled / A08-off

- **Current-state deficiency:** correct behaviour already (no reserved gap) — not a deficiency.
- **Proposed difference:** none in substance; this candidate reproduces the real "absent, not
  reserved" behaviour explicitly, alongside the real `MatchInsights` component proving deterministic
  facts are unaffected.
- **User-impact proof:** `screen.queryByTestId("assistant-coach-slot")` is `null` — no DOM node
  reserved for Assistant Coach at all.
- **Accepted trade-off:** none.

## A05-enabled-with-pattern / A08-on-strong-pattern

- **Current-state deficiency:** none — the real component already renders this correctly; this
  candidate exists because the real component cannot be fixture-driven (W4-BLK-10), not because its
  design is wrong.
- **Proposed difference:** same visual grammar (uncertainty pill, evidence/missing-evidence
  disclosure, "never changes the player's record on its own"), with simulated promote/dismiss
  instead of the real server actions.
- **User-impact proof:** evidence count and uncertainty are both inspectable from the card alone.
- **Accepted trade-off:** promote/dismiss outcomes are simulated — see `BLOCKERS.md` W4-BLK-10.

## A05-enabled-without-pattern / A08-on-no-insight

- **Current-state deficiency:** the real component renders nothing (`return null`) for this case
  too — indistinguishable from "off" at the DOM level today.
- **Proposed difference:** an explicit, honest "no useful pattern" line distinct from the "off"
  state's genuine absence.
- **User-impact proof:** `screen.getByTestId("assistant-coach-no-pattern")` exists in this state
  and not in the `off` state — a real, testable distinction the current production component does
  not make.
- **Accepted trade-off:** this is a presentation-layer proposal only; it does not change the real
  component.

## A05-unavailable

- **Current-state deficiency:** no equivalent AI-failure state exists in the real
  `AssistantCoachHypothesisPanel` today (it has no failure-state branch at all).
- **Proposed difference:** reuses the real `MatchInsights` component's own already-shipped
  `AI_UNAVAILABLE` status line verbatim ("AI interpretation is temporarily unavailable. Factual
  insights are still current."), paired with an analogous restrained notice for the hypothesis slot.
- **User-impact proof:** deterministic facts remain visible and no infrastructure detail (prompt,
  token, provider error) leaks — verified by test.
- **Accepted trade-off:** none specific to this case.
