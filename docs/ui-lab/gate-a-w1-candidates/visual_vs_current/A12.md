# A12 — Profile picker & exact-match evidence boundary: candidate vs current vs directional study

**Current:** `src/components/players/player-editor-form.tsx` (production) offers all 24 sided
`CanonicalTacticalPosition` codes for `primaryPosition`/`secondaryPosition`/`tertiaryPosition`,
via `src/lib/player-form-options.ts`. No 14-role picker, and no "collapsed profile vs exact
evidence" view existed anywhere before this PR.

**F1 Study 02 (directional, reviewed in detail for PR #777 remediation):** on the player's
**Manage tab**, the 14 profile roles render as a **permanently-expanded** flat button grid (4
columns desktop / 2 columns mobile — all 14 visible at once, no collapse/expand toggle in that
surface), sitting below three parallel PRIMARY/SECONDARY/TERTIARY dropdowns; the grid button
matching the current Primary selection is highlighted. By contrast, the **read-only Overview
tab** shows only a compact text line ("Declared primary: Forward (F)") — no button grid at all.
So the study's actual pattern is: compact text in a *read* context, the full always-visible grid
+ three dropdowns only once in a dedicated *edit* context — not a single widget that itself
collapses and expands.

**PR #777 remediation:** the previous candidate demonstrated only a single declared profile
position with no primary/secondary/tertiary structure at all. It's now a
`ProfilePositionTripleEditor` built directly on the F1 pattern above: a compact "Primary: CM ·
Secondary: RB · Tertiary: —" summary by default (mirroring the study's Overview tab), with an
"Edit" control that reveals the three PRIMARY/SECONDARY/TERTIARY selects plus the real, reused
14-button `ProfilePositionSelector` grid underneath (mirroring the study's Manage tab) — clicking
a grid button sets Primary, exactly as the study shows. Secondary/Tertiary selects exclude
whatever the other two slots already hold, so a duplicate can never be chosen in the UI
(unit-tested: `__tests__/profile-triple-selection.test.ts`); both optional slots can be cleared
back to "— None —". A legacy migration preview was added: a player whose entire historical exact
record is `LCF`/`CF`/`RCF` consolidates to a single declared `F` primary, with secondary/tertiary
left empty rather than invented — directly reproducing the study's own "No mutation"/dedup
callout for this exact LCF/CF/RCF example.

**Candidate:** `/dev/ui-lab/gate-a/a12-profile-editor` — the triple editor above, a per-slot
`LegacyEvidenceDrilldown` showing the real, un-hidden 24-code sided intervals behind each declared
slot (e.g. Primary `CM` shows `LCM — 20 min` and `RCM — 10 min`, summed to `30 min across 2
appearances`), and the legacy consolidation preview. The aggregation
(`aggregateExactAppearancesByProfile`) is unit-tested to prove it never drops, double-counts, or
rewrites a sided interval. No production wiring; this page saves nothing.

**Usability rationale:** Makes the profile-vs-exact distinction legible and auditable — a coach
sees the simplified primary/secondary/tertiary labels they declared and can still see exactly
what match evidence backs each one, without that evidence being silently merged, lost, or
duplicated across slots.
