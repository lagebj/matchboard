# A01 — Sports-first composition: candidate vs current vs directional study

**Current:** No single existing production page is a direct precedent for this exact
composition; the closest comparison is the written anti-pattern this candidate is built to avoid
(XR-S02: "no generic nested-card dashboard"). The existing `atlas-followup` UI Lab has no A01
counterpart.

**F1 Rendered Design Study 01 (directional, reviewed in detail for PR #777 remediation):** the
study's completed-match screen makes the scoreline hero by far the dominant object — the score
glyphs run roughly 4x the page title's size — with two small, clearly subordinate cards below it
(a prose "narrative" card and a compact stat-grid "facts" card). Its player-overview screen
repeats the pattern: a single large numeral ("5/5 eligible rounds") as the dominant object, a
small schematic pitch as the secondary object. No sidebar widgets, no multi-metric KPI grid, no
chart dashboard anywhere in the study.

**Candidate:** `/dev/ui-lab/gate-a/a01-sports-first` — one dominant `OperationalMatchCard`
(`variant="feature"`), two visibly smaller/secondary `TouchlineWidget`s below it (squad status
metrics, a 3-action quick-action grid). All real, shipped Touchline primitives; no new
production-facing component. The relative size relationship (one large hero, clearly smaller
secondary widgets, no competing equal-weight tiles) matches the study's intent even though the
exact components differ (the study is a standalone HTML mock, not this codebase's React
components — this candidate does not attempt pixel-identical matching, per `01_START_PROMPT_FOR_
AGENT.md`'s own instruction not to paste study markup).

**PR #777 remediation:** the "Edit lineup" quick action previously navigated to the A02
lifecycle-demonstration page — an unrelated UI Lab scenario standing in for a real action, which
violated the context-local interaction rule (XR-I01) outright. Confirmed against the F6
Interactive Study 01 directional study: its "Edit lineup" action opens a slide-in drawer over the
dimmed Match Details page, explicitly captioned "Change an exact tactical assignment without
leaving this match or opening a separate editor" and "Changing the lineup stays in this match
context" — it never navigates to a new route. The action here now opens a real, shipped
`TouchlineBottomSheet` in place, titled "Lineup", showing a read-only starting-XI preview (no
edit affordance, since this candidate never claims an editing capability it doesn't actually
have) and closing back to exactly the same page state. Relabeled from "Edit lineup" to "Lineup"
to avoid over-claiming a mutation capability this read-only preview doesn't have.

**Usability rationale:** A coach opening this page should identify the one thing that matters
(the live match) in under a second; secondary information should read as clearly subordinate.
Triggering the lineup preview must never feel like leaving the match — the bottom-sheet pattern
makes that explicit by construction (same page, same URL, dimmed backdrop, one close control).

**PR #777 remediation round 2 (missing interactive-state evidence):** the original capture only
proved the page's *initial* render — a reviewer couldn't see what the sheet actually looks like
without running it locally. `scripts/ui-lab-visual-review.mjs` now also clicks "Lineup" and
captures a second screenshot (`...-lineup-open.png`) in the same browser context, at all 3 widths
× 2 themes, and asserts the page URL hasn't changed before taking it — a real, automated guard
against the exact regression round 1 fixed. The page itself now also restores keyboard focus to
the "Lineup" trigger when the sheet closes (captured at open-time, restored on close — the shared
`TouchlineBottomSheet` component is untouched, this is app-level) and closes on Escape
(unit-tested).
