# A06 — Tactical vs profile pitch pairing: candidate vs current vs directional study

**Current:** `/dev/ui-lab/atlas-followup/position-map` shows the real, shipped
`TouchlinePositionMap` — perspective-projected, 24-code exact vocabulary, 5×6 canonical grid.
No flat, no-perspective, or 14-role counterpart existed anywhere in the repository before this
PR.

**F1 Study 02 — Position Model (directional, reviewed in detail for PR #777 remediation):** the
study's "Analytical view / Position profile" panel shows a schematic pitch, attack at the top, GK
at the bottom, with lines top-to-bottom: `F` (single centred dot) → `LW/AM/RW` → `LM/CM/RM` →
`LWB/DM/RWB` → `LB/CB/RB` → `GK`. `LWB`/`RWB` sit on their own line above the back four, visually
distinct from `LB`/`RB` — never merged into the same position. The study's separate "No
mutation"/"declared vs proven" callout states the pitch panel's dot indicates declaration, not
proven match experience, and that three declared codes (`LCF`/`CF`/`RCF`) collapse to one general
`F` role rather than three independent declarations.

**PR #777 remediation:** the candidate's flat grid previously placed `LB`/`LWB` on the same cell
and `RB`/`RWB` on the same cell — a real correctness defect, since a player can have independent
evidence at both and both must be independently visible/selectable. The repository owner's
correction (and, independently, the F1 Study 02 review above) both describe the identical
6-line ordering, now implemented exactly in `profile-position-model.ts`'s `PROFILE_FLAT_GRID`:
`F` alone on the attacking line, `LW/AM/RW`, `LM/CM/RM`, `LWB/DM/RWB`, `LB/CB/RB`, `GK` alone on
the goalkeeper line. Every one of the 14 profile positions now has a unique `(lane, line)` cell
(unit-tested: `shared/__tests__/profile-position-model.test.ts`). The fixture was also rebuilt to
exercise the full 24-code vocabulary — previously only 3 non-collapsing codes (`LW`/`LM`/`RW`)
were used, which never actually tested the 24→14 projection. It now demonstrates all five
centre-line consolidations (`LCB/CB/RCB → CB`, `LDM/CDM/RDM → DM`, `LCM/CM/RCM → CM`,
`LAM/CAM/RAM → AM`, `LCF/CF/RCF → F`) simultaneously with the wide/full-back/wing-back evidence,
each profile-level support/confidence value traceable to its strongest real exact-level source
value (unit-tested, never invented).

**Candidate:** `/dev/ui-lab/gate-a/a06-position-pitches` — left panel is the *unmodified*

**Remaining known limitation (disclosed, not resolved by this candidate):** the specific choice
of which exact-level value "wins" when aggregating a consolidated group's support/confidence into
one profile dot (this candidate uses "strongest of the group") is this candidate's own rule, not
verbatim-specified in any source document — flagged for explicit reviewer sign-off.

**Usability rationale:** Lets a reviewer see, in one page, exactly what changes (projection +
vocabulary) and what stays the same (dot visual language, evidence semantics) between the exact
tactical view and a profile-level analysis view, now with full, correct coverage of both
vocabularies.
