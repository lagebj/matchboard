## Capture provenance — local vs. CI (owner/independent review follow-up)

Local captures in this review are generated by running `scripts/ui-lab-visual-review.mjs` against
a local `next dev` server on the exact branch commit checked out at the time (`git rev-parse
HEAD`, recorded as `sourceCommitSha` in `capture-attestation.json`). The repository's own CI job
("Capture fixture-backed UI Lab views", `.github/workflows/ui-lab-visual-review.yml`) runs on
`pull_request` events, which GitHub triggers against a **synthetic merge commit** (the PR branch
merged into the current `main`) — not the PR branch's own tip commit. **A different
`sourceCommitSha`, and potentially different pixel hashes, between a local capture set and a
GitHub Actions capture set is expected and is not, by itself, an integrity failure** — it reflects
a real difference in what was actually rendered (branch tip vs. branch-merged-into-current-main),
not a corrupted or mismatched manifest. Always compare a capture set's hashes against its *own*
manifest/attestation, and check which commit that manifest actually names, rather than assuming
local and CI must byte-match.
