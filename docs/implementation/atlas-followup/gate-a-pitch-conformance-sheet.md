## Fixed during this pass (per §2 Step E's "fix them; repeat")

1. **Goalkeeper colour.** First capture rendered the GK shirt in `--warning` (amber) since it was
   the only existing neutral-ish semantic token at hand. This read as a confusing "attention"
   colour, not a kit colour. Added a dedicated `--tl-gk-kit` token (neutral grey, dark/light
   variants) and switched `PitchShirtToken` to use it.
2. **Trapezoid visibility.** The initial tuning (`topWidthFraction: 0.88`, `scaleNearAttack: 0.92`)
   was within the contract's stated range but read as nearly imperceptible at the fixture's actual
   token positions (formation-grid columns sit inset from the true pitch edges, so the visible
   narrowing was smaller than the raw edge-to-edge trapezoid). Tuned to `0.85`/`0.90` — still
   inside the contract's `84–90%`/`0.90–0.94` ranges, now clearly visible.
3. **Theme.** First capture used Playwright's default light colour scheme; the golden references
   are all dark. Re-captured with `colorScheme: "dark"` forced for a meaningful comparison.

## Comparison against the golden references

### Planning pitch (target: `03-lineup-vertical-pitch-golden.png`, `05-followup-pitch-position-system.png`)

Matches: vertical GK-bottom/attack-top orientation; dark premium green pitch material (reuses the
existing `--tl-pitch`/`--tl-pitch-deep` tokens, already tuned for this by ADR-0135); visible
top-narrower trapezoid; shirt tokens with number + name + role beneath, seated on the pitch plane
with a grounding shadow; selected halo (accent ring); locked badge; attention marker; empty-slot
dashed treatment.

Deviations (largest first):

1. **Shirt art fidelity.** `lucide-react`'s `Shirt` icon (reused from the pre-existing
   `PitchPlayerToken`) is a serviceable jersey silhouette but reads slightly blockier/less refined
   than the golden reference's shirt art. This is the same icon already shipping in production
   (`PitchPlayerToken`), not a regression introduced here — a decision to invest in custom shirt
   SVG geometry instead of the icon library is a design call for the human reviewer, not something
   to change unilaterally.
2. **Center-circle aspect.** The circle is generated by projecting real-world circle points through
   the trapezoid function, but the pitch-surface container's `aspect-[4/5]` doesn't match the real
   pitch's 68:105 proportion, so the circle reads as very slightly elongated rather than a true
   ellipse-under-perspective. Not distracting at the tested sizes, but worth a tuning pass if the
   reviewer wants exact circularity.
3. **Empty-slot label** shows the short role code in a dashed circle — close to, but not pixel-identical
   to, the golden reference's empty-slot treatment (which the reference doesn't show explicitly for
   every case). No change made without a clearer reference to match.
4. Bench/candidate rail and the selected-player detail sheet shown in the golden reference belong
   to the full Lineup route composition (Phase F7), not the pitch component in isolation — correctly
   out of scope for this Phase F2 fixture, noted so it isn't mistaken for a gap in the pitch itself.
5. Mobile capture (390×844, 360×800) renders the same component at full width with no horizontal
   scroll and no layout breakage — no deviation found at either mobile viewport.

### Position map (target: `05-followup-pitch-position-system.png`'s "PLAYER DETAIL POSITION MAP" panel)

Matches: flat, no perspective; GK-bottom/attack-top; dark pitch material; green dots only, hue
varies by support band, confidence via opacity/outline, no dot for unsupported positions (CB
absent in the fixture, correctly renders no dot).

Deviations:

1. The golden reference's dots are plain circles with an external text legend; this implementation
   embeds the position code as text *inside* the rank-1 (primary) dot only. A deliberate choice for
   at-a-glance identification without a separate legend, but a genuine visual difference from the
   reference the human reviewer should confirm or reject.
2. A `LIMITED`/`LOW`-confidence dot (the ST example in the fixture) is quite faint by design — this
   is correct per the contract ("confidence... opacity... ") but borderline hard to spot at a glance;
   worth confirming the minimum visible opacity/size is acceptable rather than effectively invisible.

### Team Kit Colour (`NORMAL` gate, not golden-sensitive — included for completeness)

Clean, legible at every size (`xs` 20px through `hero` 96px), correct automatic text-colour
contrast on every palette swatch (verified both visually and by the `getReadableTextColor` unit
tests), and all four states (normal/selected/muted/neutral) read distinctly.
