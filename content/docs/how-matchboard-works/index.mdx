The rest of this documentation shows you how to use each page. This section explains the
reasoning underneath: what Matchboard actually uses when it proposes a squad, a starting
lineup, or a rotation plan, what always takes priority over what, and what it explicitly does
not know or claim.

## Why this section exists

Matchboard makes recommendations — a draft squad, a suggested lineup, a proposed rotation
sequence. A recommendation is only useful if you can trust it, and you can only trust it once
you know what went into it. "Click Generate" is not an adequate explanation for a system that
affects which children play, and how much.

Every page in this section tries to answer the same small set of questions for one mechanism:

- What information did Matchboard use?
- Which constraints took priority over which?
- Why could this recommendation reasonably differ from another one?
- What here is historical fact, and what is an observed pattern?
- What can you change, and how?
- What is Matchboard explicitly not claiming to know?

## What this section is not

This section explains product behaviour, not source code. It does not expose internal helper
names, database field names, or every intermediate number a scoring function happens to
compute. Where a number materially changes what you should expect (for example, how a repeated
support assignment is treated), it is stated plainly. Where the underlying mechanism is a
weighted preference among several reasonable options, it is described as that — an ordered set
of influences, not a formula to memorize.
